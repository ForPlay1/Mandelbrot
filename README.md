# FractalCipher — фрактальное шифрование изображений

Учебный проект: шифрование изображений на основе фрактальных перестановок
и хаотических карт. Реализован на Java 17+ с JavaFX-интерфейсом.
Каждая операция полностью обратима, ключи сохраняются отдельно, есть
исследовательский бенчмарк с набором стандартных метрик.

## Идея

Обычные шифры (AES, ChaCha20) работают с байтовым потоком и «не видят»
структуры изображения. Здесь используется противоположный подход:
**шифр знает, что перед ним картинка**, и применяет два этапа, специально
предназначенных для пиксельных данных:

1. **Перестановка** — пиксели меняются местами по псевдослучайному
   закону, порождённому фракталом (Мандельброт, Жюлиа, Кантор, ...).
2. **Диффузия** — значения каналов R/G/B меняются по псевдослучайному
   потоку, порождённому хаотической картой (логистическая, Хенон,
   Лоренц, ...).

После обоих этапов изображение визуально неотличимо от шума, но
**полностью восстанавливается** при наличии ключа (MSE = 0).

## Возможности

- Одиночное **шифрование** и **расшифровка** изображений.
- **Пакетная** обработка папки (шифрование и расшифровка).
- **Бенчмарк**: перебор всех комбинаций «перестановка × диффузия»
  с замером корреляции, энтропии, NPCR, UACI, MSE и времени.
- **7 хаотических карт** для диффузии и **6 фракталов** для перестановки
  (плюс identity-заглушка).
- Три режима шифрования: только перестановка, только диффузия, полная
  схема с CBC и S-боксами.
- Диалог «Файл уже существует» в стиле проводника Windows:
  заменить / пропустить / применить ко всем.
- Устойчивость к коллизиям имён: `photo.png` и `photo.jpg` из одной
  папки не затирают друг друга.
- Логирование в `logs/` с ротацией и отдельным файлом для критических
  ошибок.
- Централизованная обработка ошибок с безопасными сообщениями для UI.

## Как это работает

### Схема полного шифрования

```
оригинал ──► [ перестановка ] ──► [ диффузия + CBC ] ──► шифротекст
             (фрактал)            (хаотическая карта)
```

**Расшифровка** снимает шаги в обратном порядке:

```
шифротекст ──► [ снять CBC ] ──► [ обратная перестановка ] ──► оригинал
               (invSbox)            (invertPermutation)
```

### Откуда берутся все параметры

Мастер-ключ (32 случайных байта) — единственное, что нужно знать для
расшифровки. Все остальные параметры выводятся из него детерминированно
через SHA-256 с **доменной сепарацией**:

```
"perm:mandelbrot"              → seed перестановки
"diff:logistic"                → seed потока диффузии
"x0:logistic"                  → начальное значение карты
"sbox:logistic"                → seed S-бокса в потоке
"cbc1:logistic", "cbc2:logistic" → seed-ы S-боксов CBC
```

Это гарантирует: один и тот же ключ + одно и то же изображение → один
и тот же шифротекст. И наоборот: изменение любого бита ключа полностью
разрушает результат (лавинный эффект).

### Контекстный параллелизм

Параллелизм применяется **по-разному** в зависимости от количества
файлов:

| Что обрабатывается | Что параллелим | Внутренний параллелизм фрактала |
|---|---|---|
| Один файл | Внутри фрактала/карты | Включён (`isParallel = 1.0`) |
| Папка из N файлов | N файлов через `parallelStream` | Выключен (`isParallel = 0.0`) |

Так избегается «thread starvation», когда N файлов × M ядер порождают
N·M потоков и ОС начинает «дёргать» их вместо полезной работы.

## Алгоритмы

### Источники перестановки (`PermutationSource`)

| Имя | Формула / идея | Особенность |
|---|---|---|
| `mandelbrot` | `z = z² + c`, escape-time | Классика, стабильный результат |
| `julia` | `z = z² + c`, но `c` — часть ключа | Разнообразие за счёт `c` |
| `burning ship` | `z = (\|Re z\| + i·\|Im z\|)² + c` | Характерная «горящая» форма |
| `cantor` | Функция спаривания Кантора | Быстрая, без «тяжёлой» математики |
| `sierpinski` | `(x & y) == x` как «расстояние до множества» | Очень быстрая |
| `dragon` | Кривая Дракона + distance transform | Плавные градиенты весов |
| `identity` | Тождественная (только для бенчмарка) | Не меняет порядок |

### Источники диффузии (`DiffusionSource`)

| Имя | Уравнение / идея | Арифметика |
|---|---|---|
| `logistic` | `x → r·x·(1−x)`, `r ≈ 3.99` | `double` |
| `henon` | `x → 1 − a·x² + y, y → b·x` | `double` |
| `tent` | Кусочно-линейная, параметр `mu` | `double` |
| `lorenz` | Система ОДУ, RK4, классические параметры | `double` |
| `rossler` | Система ОДУ, RK4 | `double` |
| `arnold` | Кошачья карта на торе | **`long` (mod 2⁶⁴)** — точная биекция |
| `null` | Нулевой поток (заглушка) | — |

### Режимы (`EncryptionMode`)

| Режим | Перестановка | Диффузия | CBC | S-боксы |
|---|---|---|---|---|
| `PERMUTATION_ONLY` | ✓ | нулевой поток | ✗ | ✗ |
| `DIFFUSION_ONLY` | identity | ✓ | ✗ | ✗ |
| `FULL` | ✓ | ✓ | ✓ (2 прохода) | ✓ |

Режимы используются в бенчмарке, чтобы оценить вклад каждого этапа
отдельно. Реальное шифрование всегда идёт в `FULL`.

- **JDK 17** или новее (используются `switch`-выражения, `record`,

## Запуск

### Из IDE (IntelliJ IDEA / Eclipse)

1. Открыть проект как Maven/Gradle (или просто «Open folder»).
2. Убедиться, что в Project Structure указан JDK 17+.
3. Запустить `fractalcipher.run.Main`.

### Через `java -jar`

Если собран `.jar` с манифестом:

```bash
java -jar fractalcipher.jar
```

Для JavaFX нужны модули `javafx.controls` и `javafx.graphics` — они
должны быть либо в `--module-path`, либо в classpath.

### Сборка

```bash
# Maven
mvn clean package

# Gradle
./gradlew build
```

Готовый артефакт — в `target/` (Maven) или `build/libs/` (Gradle).

## Использование

### Интерфейс

Окно разделено на две части: **левая панель** (выбор параметров) и
**область предпросмотра** (справа).

Порядок действий:

1. **Выберите режим**: Шифрование / Расшифровка / Бенчмарк /
   Шифр. папки / Расшиф. папки.
2. **Выберите вход**: файл (для одиночных режимов) или папку (для
   пакетных). Можно перетащить мышью.
3. **Выберите методы** — только для режимов шифрования. Для расшифровки
   методы берутся из `.key`-файла.
4. **Выберите папку результата** — для всех режимов, кроме бенчмарка.
5. **Нажмите «Запустить»**.

Если в папке результата уже есть файлы с целевыми именами — появится
диалог «Файл уже существует» с опциями **Заменить / Пропустить /
Применить ко всем**.

### Именование файлов

| Операция | Вход | Выход | Ключ |
|---|---|---|---|
| Шифрование | `photo.png` | `photo_png_encrypted.png` | `photo_png_encrypted.key` |
| Расшифровка | `photo_png_encrypted.png` | `photo_png_decrypted.png` | (читается из `photo_png_encrypted.key`) |

Расширение входит в имя — `photo.png` и `photo.jpg` из одной папки
дают **разные** целевые файлы и не затирают друг друга.

## Формат ключей

Ключ — бинарный файл `.key` рядом с зашифрованным изображением.
Содержит:

- `masterKey: byte[32]` — 256-битный мастер-ключ;
- `permutationSourceName: String` — имя фрактала (например, `"mandelbrot"`);
- `diffusionSourceName: String` — имя карты (например, `"logistic"`).

Сериализуется стандартным `ObjectOutputStream`. При расшифровке
методы берутся из ключа, а не из UI — поэтому пользователю не нужно
помнить, чем именно шифровали.

> ⚠️ Файл `.key` — **единственный** способ расшифровать изображение.
> Потеря ключа = потеря данных, восстановление невозможно.

## Бенчмарк и метрики

Бенчмарк перебирает все комбинации алгоритмов и сохраняет CSV в
`benchmarks/benchmark_<имя_входа>_<timestamp>.csv`.

### Три серии

| Серия | Перестановка | Диффузия | Что измеряет |
|---|---|---|---|
| Только перестановка | все | `null` | Вклад перестановки в разрушение корреляции |
| Только диффузия | `identity` | все | Вклад карт в лавинный эффект |
| Полная схема | все | все | Итоговую криптостойкость |

### Метрики

| Метрика | Идеал | Что показывает |
|---|---|---|
| **Correlation** | ≈ 0 | Соседние пиксели независимы |
| **Entropy** | ≈ 8 | Равномерное распределение яркостей |
| **NPCR** | > 99.6% | Сколько пикселей меняется при изменении 1 бита входа |
| **UACI** | ≈ 33.4% | Средняя сила изменения пикселей |
| **MSE** | 0 | Идеальное обратимое восстановление |
| **TimeMs** | (меньше — лучше) | Время шифрования одного изображения |

### Формат CSV

```
ImageName,BlackAndWhite,Permutation,Diffusion,TimeMs,Correlation,Entropy,NPCR,UACI,MSE
photo.png,false,mandelbrot,logistic,1234,0.0123,7.9987,99.62,33.45,0.0000
```

Флаг `BlackAndWhite` позволяет анализировать алгоритмы отдельно на
чёрно-белых и на цветных изображениях.

### Анализ в pandas

```python
import pandas as pd
df = pd.read_csv("benchmarks/benchmark_dataset_2026-11-12_15-42.csv")

# Средние метрики по парам алгоритмов
print(df.groupby(["Permutation", "Diffusion"])[["Correlation", "Entropy", "NPCR", "UACI"]].mean())

# Сравнение B/W vs RGB
print(df.pivot_table(index=["Permutation", "Diffusion"],
                     columns="BlackAndWhite",
                     values=["NPCR", "UACI"]))
```

## Архитектура

### MVC с «голым» контроллером

```
View (JavaFX)  ──►  Map<Class<?>, Object>  ──►  Controller  ──►  Model
                    (getUserParams())           (processSelection)
```

- **View** не знает про Controller — она только публикует выбор в
  статическом поле `MainView.getUserParams()`.
- **Worker-поток** в `Main` замечает смену ссылки и вызывает
  `Controller.processSelection(...)`.
- **Controller** разбирает выбор и вызывает методы модели
  (`FractalChaosCipher`, фабрики источников).

Такое разделение позволяет:
- тестировать Controller без UI (создать `Map` вручную);
- менять UI (JavaFX ↔ Console) без правок Controller;
- выполнять тяжёлую работу вне JavaFX Application Thread.

### Паттерны

| Паттерн | Где | Зачем |
|---|---|---|
| **Template Method** | `Cipher.encrypt()` | Фиксированный порядок шагов (preprocess → process → postprocess) |
| **Strategy** | `PermutationSource`, `DiffusionSource` | Взаимозаменяемые алгоритмы |
| **Factory** | `PermutationSourceFactory`, `DiffusionSourceFactory` | Регистрация по имени, отвязка от конкретных классов |
| **MVC** | View / Controller / Model | Разделение ответственности |
| **DTO** | `BenchmarkResult` | Иммутабельная запись результата |

## Ограничения и известные нюансы

- **Не для production.** Проект учебный. Ключ хранится в открытом
  виде рядом с изображением, мастер-ключ не защищён паролем. Для
  реального применения нужны KDF с паролем, безопасное хранилище
  ключей и аудит криптостойкости.
- **Сериализация ключа через `ObjectOutputStream`** — при изменении
  структуры `EncryptionKey` старые `.key` перестанут читаться
  (`serialVersionUID` нужно будет увеличивать).
- **Эвристика `isBlackAndWhite`** — приблизительная. Для почти-серых
  JPEG возможны ложные срабатывания (порог `CHANNEL_THRESHOLD = 8`).
- **Параллельная генерация диффузии** для карт с прогревом (Хенон,
  Лоренц, Рёсслер) не совпадает побитово с последовательной — но
  воспроизводима при одинаковом наборе параметров.
